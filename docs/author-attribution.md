# issue: author-attribution — 在每个 kiln 动作上标明其作者（人 / Agent）

- **domain**：design

## 背景

`kiln commit` 产出的每个动作都是一条提交，但**看不出来源**：是人拍的板，还是 agent 生成的草稿？而且现状**所有提交共用同一个 git 身份**（Jackie Han），人 / agent、这个 agent / 那个 agent 全糊在一起——归属信息量≈零。

## 要回答的问题

1. 加一个"作者"字段**有没有用**？
2. 人这边 git 已有身份标识，**agent 要不要也标**？
3. 不同 agent 要不要**再区分到会话**？**同一 agent 的不同会话算同一个 agent 吗**？
4. 用 **git 身份**还是**新增 trailer**承载？

## 探讨：身份单元有三层

| 层级 | 是什么 | kiln 现成的 | 稳定 / 可核验 | 能表达 |
| --- | --- | --- | --- | --- |
| **人** | 具体的人 | git author（`%an/%ae`） | 是（+签名可绑定） | 谁拍的板 |
| **Agent** | 软件 / 模型 | 无 | 中（靠约定） | 人 vs 机器 / 哪个 agent |
| **会话** | 一次运行 / 一段对话 | 无 | 差（id 随机、跨 clone 不稳） | 哪个上下文做的判断 |

关键分叉——**"同一个 agent 的不同会话算不算同一个 agent"**，取决于定义：

- **A：agent = 软件 / 模型身份** → 所有会话是同一个 agent，会话只是**子属性**；
- **B：agent = 有独立上下文的行动者** → 会话之间不共享记忆，做 `ask` 的会话与做 `conclude` 的会话是**两个互不知情的心智**，甚至可能互相矛盾——**会话才是真身份**。

B 更贴 kiln 的用途（复盘"判断在什么条件下做出"），但**会话 id 随机、跨 clone 不稳、事后无从核验**——写进 trailer 等于引入一个**不可核验的噪声字段**，比"人 vs agent"的粗粒度**更糟**。

机制两条路线：

| 路线 | 成本 | 弱点 |
| --- | --- | --- |
| ① **git 身份**（`%an/%ae`） | 零新 trailer | 需给每个 agent 配独立身份；共用身份 = 无信息 |
| ② **新增 trailer**（`author:` / `by:` / `agent:`） | 每次手写 | 与 git author **重复**；手写易漂移 |

两点补充：

- **可伪性**：改 `user.name` 与写 trailer 一样容易；真正能**绑定**身份的只有**签名（GPG/SSH）**——那是 git 的能力，不是 trailer 的。
- **git 能表达"双角色"**：author（想的人）/ committer（提交的人）。"人给需求、agent 落地"时二者可不同——这恰是归属里最有价值的一条，**trailer 反而难做**。

## 结论（已定）

**不做。必要性不足，留待需要时再评估。**

理由：

1. **今天没有消费场景**：同库只有 1 个人 + 1 个 agent，且**共用同一个 git 身份**；加字段也区分不出任何东西——**没有东西读的字段就是装饰**，与 kiln"只读 + 呈现"的取向相悖。
2. **更细的粒度各有硬伤**：agent 级靠约定、可伪；会话级语义最真但**不可核验**。
3. **真要区分时，git 本身就够**：给每个 agent 配独立 git 身份，`%an/%ae` 自动生效——零新增语法、零漂移，还能顺带用上 author/committer 双角色与签名。

**重启触发条件**（满足任一再重新评估）：

- 出现**第二个行动者**在同一仓库提交（第二个 agent，或另一个人的独立身份）；或
- 出现**具体的消费场景**：`check` 需要据此校验 / `list --author=` 过滤 / `path`、`show` 渲染要区分"人 vs agent"。

届时再定：记到哪一层（人 / agent / 会话）、走 git 身份还是 trailer。

## 非目标

- 本轮不改代码、不新增 trailer。
- 不定义"agent 的边界"（模型级 vs 会话级）——留到重启时作为第一问。

# i18n：把 kiln 的文案做成可切换语言

## 背景

kiln 的 CLI 帮助、错误、提示、`check` 的人读文案、`status` / `list` / `graph` / `path` 的文本视图，以及 README、49 份 `docs/`，目前全是硬编码中文。机器可读输出是例外：7 个 `--json` 用英文键、英文 rule 码，`checkResult` 只有 `rule` 没有 message——这一层本来就不带语言。

[docs/readme.md](readme.md:26) 当初把「README 用中文、不做英文版」写成决定，并注明「要则另开 issue」。本 issue 就是那次另开：不是只翻 README，而是问整个项目怎么支持多语言。

## 问题

1. **翻哪些文本**：帮助 / 用法、运行期错误与警告、提示与完成行、`check` 的 message、文本渲染器的标题与空态、种子配置里的注释、README 与 docs。
2. **语言怎么选**：命令行 flag、环境变量、仓库配置，还是自动探测 `LANG`？默认哪种、优先级如何？
3. **用什么机制**：仓库零依赖（`go.mod` 无 `require`、产物是单文件），要不要为此引入 `golang.org/x/text` 或 `.po` 构建步骤？
4. **测试怎么不被语言耦合**：现有 181 个测试里有 198 行断言含中文子串。
5. **文档怎么办**：README 双份？49 份 docs 翻不翻？
6. **JSON 翻不翻**：预期不翻——机器可读是稳定面，翻键会破坏调用方。

## 候选（机制 × 范围）

| 方案 | 做法 | 代价 |
| --- | --- | --- |
| **A 单语英文** | 直接把 CLI 与 README 改成英文，不再保留中文 | 改动最小，但现有中文使用者（作者与团队）被抛下；docs 仍是中文，内英混杂 |
| **B 内置双语 catalog** | 新增 `internal/i18n`：`T(lang, key, args…)` + zh/en 两套 Go map；文本从 cli / engine / config 移进 catalog；`KILN_LANG` 与全局 `--lang` 选语言，默认中文；JSON 不动 | 要搬约 177 行 Go 文案并补测试；零依赖、单文件不变 |
| **C `x/text/message`** | 用标准 i18n 库 + `gotext` 生成 catalog，支持复数与 CLDR 格式化 | 引入依赖与构建步骤；kiln 文案量小，收益不成比例 |
| **D 只翻一半** | 只翻 help / 错误，`status` / `list` / `graph` 文本视图保留中文 | 英文使用者看到中英混杂，等于没翻 |
| **E 只翻文档** | `README.en.md` + docs 英文摘要，CLI 保持中文 | 对「装完命令不会读」的人帮助有限 |
| **F gettext `.po`** | 文案抽成 `.po`，运行时解析或编译 | 要写解析器或加构建步骤；触发与 C 相同的零依赖问题 |

关键判断：**JSON 层已经语言中立**，所以 i18n 的战场全在文本层。若选 B，范围可以一次覆盖 CLI 全部文本，且默认中文让现有测试与用户都不受影响——这是推荐 B 的理由；D / E 只解决问题的一半。

## 验收

- **E1** `KILN_LANG=en kiln -h` 与 `kiln --lang en -h` 输出全英文、无中文；默认与 `KILN_LANG=zh` 的输出与今天**逐字节相同**（除新增的 `--lang` 说明行）。
- **E2** `en` 下错误、警告、提示、完成行全英文；`zh` 下不变。
- **E3** `check` 文本 message 双语；`check --json` 的 `rule` / `ref` / `relation` 字节不变、不含 prose。
- **E4** `status` / `list` / `graph` / `path` / `show` 的文本视图双语（标题、空态、计数）；同名命令的 `--json` 输出不受语言影响。
- **E5** 默认中文下既有 181 个测试不改断言仍全绿；新增 en 用例覆盖 help / 错误 / check message / 空动作提示；`gofmt` / `go vet` / `go test ./...` 全过。
- **E6** 种子配置（`kiln config path` 首次写入）的注释跟随当前语言，或明确固定中文——二选一，在 hypothesize 里定。

## 非目标

- 不翻 `--json` 的键、action / relation 词表、rule 码、trailer 键——机器可读面保持英文。
- 不做「每仓库配置语言」：语言是用户偏好，不是项目共享；`.kilnconfig.jsonc` 不放 `lang`。
- 不引入第三方依赖或额外构建步骤（若走 B）。
- 本轮不改 README 与 docs 的语言（文档切片另开或后续追加）。

## 开放问题

- 默认中文还是自动探测 `LANG` / `LC_ALL`？自动探测会让 CI 与老环境的输出漂移，倾向默认中文、显式 opt-in。
- 全局 `--lang`（`kiln --lang en status`）还是每命令 flag？前者要动 `Run` 的分发与 `-h` 的特判，后者要重复实现，倾向全局。
- 英文文案的措辞由谁定？建议沿用现有简短风格，并禁止把 rule 码翻译成句子。

### 已经语言中立的部分

- 7 个 `--json`：键、action / relation 词表、rule 码、`missing` / `directed` 都是英文；`checkResult`（cli.go:2008）没有 message 字段，`check --json` 只给 `rule` + 可选 `ref` / `relation`。
- trailer 键与提交信息（`issue:` / `action:`）是英文。
- 排序与计数不随 locale 变。

### 测试耦合的形状

```go
// internal/cli/cli_test.go 里的典型断言
if !strings.Contains(errOut, "未知 flag --bogus") { ... }
if !strings.Contains(text, "已提交") { ... }
```

`engine_test.go` 有 67 行中文断言（check message 与渲染），其余在 `cli_test.go`。默认语言保持中文，则这些断言一行都不用改；默认一改英文就会全红。

### 帮助文本的形状

- `usageText`（cli.go:97）按终端显示宽度对齐；ASCII 宽度即列宽，en 下这层逻辑仍可用，但每列宽度会变，任何快照测试要跟着变。
- `doCommitFlagGroups`（cli.go:77）从 `model.RelationSet` 生成关系 flag 帮助，gloss 来自 `RelationName.Gloss`——翻译要落到词表，不能 hardcode 在 cli。

### 相关决定

- [docs/readme.md](readme.md:26)：「语言：中文……英文版另说」；:45「不做英文版（要则另开 issue）」。
- `machine-readable-output` 的约定「JSON 不写给人看的东西」直接说明 JSON 层不需要 i18n。

## hypothesize（2026-10-23，设计提案，待定）

**选 B：内置零依赖 catalog，一次覆盖文本层，默认中文。**

### 裁定

1. **机制**：新增 `internal/i18n`。
   - `type Lang string`；`Zh` / `En` 两个常量；`T(lang Lang, key string, args ...any) string` 查 catalog，缺 key 原样回显（测试一跑就暴露漏翻）。
   - catalog 用 Go map（`catalog.go`），zh/en 两份；不引 `golang.org/x/text`：文案只有数字插值、没有复数与日期格式化，CLDR 的收益为零，反而破坏零依赖与单文件。
   - `Resolve(flagValue string, env func(string) string) Lang`：优先级 `--lang` > `KILN_LANG` > `zh`；未知值在 dispatch 前报错 exit 2（不静默回退）。
2. **语言选择**：`KILN_LANG` 环境变量 + 全局 `--lang <zh|en>`。不做 `.kilnconfig.jsonc` 的 `lang`：语言是用户偏好，配置是项目共享。
3. **范围**：帮助 / prologue / flag help / relation gloss；所有 stderr 与 stdout 的 prose；`engine.Diagnostic.Message`；`status` / `list` / `graph` / `path` / `show` 的标题与空态；种子配置注释跟随当前语言（E6 取「跟随」）。
4. **不动的**：`--json`、rule 码、action / relation 词表、trailer 键、用户数据（title / refs / tags / domain）。
5. **测试**：默认 zh，既有 181 个测试与断言零改动；新增 i18n 单元测试（zh/en key 集合相等、en 值无汉字、缺 key 回显）与 en 端到端测试（`t.Setenv("KILN_LANG","en")`，断言输出无 CJK，覆盖 help / 错误 / check message / 空动作提示）。

### 迁移顺序（每步 zh 输出逐字节不变，靠现有测试守）

1. `internal/i18n` 骨架 + `Resolve` + 在 `Run` 入口接 `--lang` / `KILN_LANG`（先只翻 usage）。
2. 错误 / 警告 / 提示（cli.go 各 `Fprintf(errw, …)` 与 `提示:` 行）。
3. `check` message（engine.go 4 条 +「完整」+ `NoDomain`）。
4. 文本渲染器（status / list / graph / path / show）。
5. 种子配置注释 + relation gloss。

### 风险

- **文本抓取**：`--json` 是稳定面；README 补一句「解析输出请用 `--json`」，并说明文本视图可能随语言变化。
- **`--lang` 放全局**要动 `Run` 的分发（在 `-h` 特判之前消费），改动集中在入口一处。
- **宽度对齐**：en 更短，测试别断言整行长度；`usageText` 的对齐算法本身可复用。
- **默认中文 + 显式 opt-in**：英文用户要设 `KILN_LANG=en`；自动探测 `LANG` 会让 CI 输出漂移，按非目标排除。

### 待拍板

- 是否接受「默认中文 + 显式 opt-in」（而不是自动探测）。
- 英文文案的措辞由谁复核（建议以「短、动词开头、不解释 rule 码」为准）。
- README / docs 英文版另开切片（建议另开，保持本 issue 只做 CLI 文本）。

### 机制

`internal/i18n`（零依赖，单文件产物不变）：

- `Lang` / `Zh` / `En`；`Set` / `Current`。
- `Detect(locale)`：小写以 `en` 开头即英文，其余归中文。
- `Parse(s)`：显式值 `zh` / `zh-cn` / `zh_cn` / `zh-hans` / `chinese` / `中文`，`en` / `en-us` / `en_us` / `en-gb` / `en_gb` / `english`。
- `ResolveFromEnv()`：`KILN_LANG`（先 `Parse`，非法则忽略）→ `LC_ALL` → `LC_MESSAGES` → `LANG` → `Zh`。
- `T(source, args…)` / `E(source, args…)`：**按中文原文串查表**，不是按 key。查不到就原样回显——漏翻的字符串在英文下会露出中文，一眼可见，不会打印 `i18n.key.xxx`。`E` 走 `fmt.Errorf`，`%w` 的 unwrap 链保留。
- `catalog.go`：`map[string]string`，键是源码里的中文原文（含 4 个多行块：usage 头 / prologue / 其它 flag / 种子配置整份），值是对应英文。测试强制 **en 值无汉字**、**en 与 key 的格式动词序列一致**（否则 `%s` 顺序错位会打出 `%!s(MISSING)`）。

### 接入点

- `internal/cli/cli.go`：`Run` 入口先 `extractLang(args)` 消费全局 `--lang <v>` / `--lang=<v>`（缺失值 / 非法值 exit 2，stdout 0 字节），然后把 flag 从 args 里摘掉再分发；无 flag 时 `i18n.Set(i18n.ResolveFromEnv())`。usage 的 `--lang` 说明行写进 `usageOtherFlags`。
- 文本层全部换成 `i18n.T`：帮助（header / prologue / 命令表 / flag 分组与 gloss）、错误与警告、`提示:`/`已提交`/`将提交` 等完成行、`check` 的 4 条 message 与「完整」、`status` / `list` / `path` / `show` / `worktree list` 的标题、状态词（`干净`/`有改动`/`未合并`/`目录已删`）、图例、`NoDomain`（`(未分类)`）、relation gloss（9 条）、`vcs` 的「不在仓库里」与后端错误、种子配置注释（`i18n.T(defaultFile)`，E6 取「跟随」）。
- **不翻**：`--json` 的键、rule 码、action / relation 词表、trailer 键、用户数据（title / refs / target / scope / domain / tags / 提交正文）。
- `worktreeTip` 的三种拒绝语按 main 的脏/净分支整体翻译（中文各是一整句，英文对应整句，不拼接碎片）。

### 边界

- `path` / `show` / `graph --json` 会原样带出 issue title 与提交正文——那是用户数据，**永远不翻**；「en 下无汉字」只对 UI prose 成立。
- 文本视图的列宽按终端显示宽度算，英文更短，列宽会变；不要对整行宽度做快照。
- 文档层只有根 README 双语（`README.md` / `README.en.md`，顶部互相链接）；`docs/` 仍全中文——英文读者要读设计理由只能看中文，这是本轮的明确取舍。
- 配置里的 action 词表仍是用户数据，不参与翻译；`status` 的 domain 名同理。
- 语言是**进程级**状态：同一个进程里跑两次 `Run`，第二次会重新按 args/env 设置，不会继承上一次。

# issue: evidence-fluidity — 动作「证据」可被改写 / 删除，与 kiln「记录」取向的张力

- **状态**：ask（进行中）
- **domain**：design
- **关联**：blocks `cli-necessity`

## 背景

`kiln` 的隐含前提是：**一个 issue 的动作历史 = 它求解过程的记录（证据）**。`path` 重建这条路径、`show` 展示每一步变更、`check` 校验其结构——都建立在"历史**可信且稳定**"之上。

但 `cli-necessity` 的后端实证（实验 3/4）表明，在 **jj** 上这个前提**不成立**：

- **改写**（`jj describe`）：动作的 `commit_id` **漂移**（`3a6a9ba`→`9b5185c`），后代自动 rebase；只有 `change_id` 稳定。
- **删除**（`jj abandon`）：一个动作**秒删**，kiln 视图立即少一步。
- **撤销**（`jj undo`）：又可原样恢复。
- `jj op log` 全程记录"哪一步做了什么"。

也就是说：**在 jj 上，任何一条动作证据都能被任意改写 / 删除 / 复原**。git 也有同类能力（`rebase` / `commit --amend`），只是**危险、显式、少见**；jj 把它变成了**日常操作**。

## 要回答的问题

1. **取向先定**：kiln 把动作历史当**不可变证据（记录）**，还是**可改写草稿**？这条不先答，其余都悬空。
2. **若当证据**：
   - 怎么**检测"被改写过"**？jj 有 **op log**（能直接说"describe / abandon 了哪条"）；git 只有 **reflog**（弱、本地、会过期）——两端能给的信号**不对等**。
   - 检测到之后**怎么表现**？`path` 给该动作标"⚠ 已重写"，还是让旧 id 显式失效？
3. **寻址稳定性**：kiln 现靠 `path` 里的**序号**寻址（`action-diff` 的决定）。历史一改，序号**重算但仍自洽**——这算"够用"，还是需要更硬的标识（`change_id`、内容哈希）？
4. **要不要"不可变"机制**：给动作加**内容哈希 / 签名**（内容一变就露馅），还是只立"**不改写已归档动作**"的社会约定（零机制）？
5. **git 后端是否同病**：`rebase` / `amend` 同样能改，只是不常见——规则该只针对 jj，还是两端一视同仁？

## 候选

| 方案 | 形态 | 代价 |
| --- | --- | --- |
| **A** 只立约定 | "已归档动作**不得改写**"，靠自觉 | 零机制；无法强制、无检测 |
| **B** 检测 + 提示 | 用 jj **op log**（git 用 reflog）标出"该动作被重写"，`path` 显示警告 | 只能事后提示；git 端信号弱 |
| **C** 不可变标识 | 动作提交里带**内容哈希**，内容一变即与声明不符 | 又加一个字段，且与 trailer"自述"同类问题 |
| **D** 承认是草稿 | 明确"kiln 只读当前态、不做证据保证"，**放弃**"记录"承诺 | 削弱 kiln 的核心卖点之一 |

> 倾向（待验证）：**A + B**——用约定兜底、用 op log 做**可选的**检测提示；C 过重、D 自弃。

## 为什么这会阻塞 cli-necessity

`cli-necessity` 要定的是"kiln 的 CLI 该留哪些能力"，其中"**动作路径 = 可信记录**"是一条重要的能力主张。若这条在 jj 上不成立，"留 `path` / `show`"的理由就要重新掂量。**先答清"证据到底可不可信"，才能定"要不要为它保留能力"**——故本 issue **`blocks` `cli-necessity`**。
